树状数组（Binary Indexed Tree，简称 BIT，又称 Fenwick Tree）是一种用于高效处理**动态前缀和**的数据结构。它能够以极小的常数和代码量，将单点修改和前缀和查询的时间复杂度都从 $O(N)$ 优化到 $O(\log N)$。

## 1. 原理剖析

树状数组的核心思想是利用**整数的二进制表示**来进行区间的划分。任何一个正整数都可以拆分成若干个 $2$ 的幂之和。树状数组用一个数组 `c[]` 来维护原数组 `a[]` 的某些区间的和。

### 核心函数：`lowbit(x)`

`lowbit(x)` 返回数字 $x$ 在二进制表示下最低位的 `1` 及其后面的 `0` 构成的数值。

例如：$6$ 的二进制是 `0110`，其最低位的 `1` 代表数值 $2$，所以 $\text{lowbit}(6) = 2$。

利用计算机的补码性质，可以极快地计算：

$$\text{lowbit}(x) = x \ \& \ (-x)$$

### 数组 `c[]` 的含义

数组 `c[x]` 并不单纯等于 `a[x]`，而是代表原数组中一段**长度为 $\text{lowbit}(x)$ 的区间和**。

具体来说，`c[x]` 管辖的区间是：

$$[x - \text{lowbit}(x) + 1, x]$$

- `c[1]` = `a[1]` (长度为 1)
    
- `c[2]` = `a[1] + a[2]` (长度为 2)
    
- `c[3]` = `a[3]` (长度为 1)
    
- `c[4]` = `a[1] + a[2] + a[3] + a[4]` (长度为 4)
    
### 操作路径

- **查询前缀和（向下累加）：** 要查询 $x$ 的前缀和，只需将 `c[x]` 加上，然后剥离掉 $x$ 的最低位 `1`（即 $x = x - \text{lowbit}(x)$），继续累加，直到 $x=0$。这实际上是在把前缀区间拼凑起来。
    
- **单点修改（向上更新）：** 如果修改了 `a[x]`，需要更新包含 `a[x]` 的所有 `c[]` 节点。更新路径为：不断加上自己的 `lowbit`（即 $x = x + \text{lowbit}(x)$），去更新父节点，直到超出数组最大范围 $N$。 
    

## 2. 代码实现 (C++)

树状数组的代码实现极为精简，几乎没有边界特判。
  
C++

```C++
#include <vector>

class FenwickTree {
private:
    int n;
    std::vector<int> c;

    // 获取最低位的 1
    int lowbit(int x) {
        return x & (-x);
    }

public:
    // 初始化树状数组，大小为 n
    FenwickTree(int n) : n(n), c(n + 1, 0) {}

    // 单点修改：将 a[x] 加上 k
    void add(int x, int k) {
        for (int i = x; i <= n; i += lowbit(i)) {
            c[i] += k;
        }
    }

    // 前缀和查询：求 a[1] 到 a[x] 的和
    int query(int x) {
        int sum = 0;
        for (int i = x; i > 0; i -= lowbit(i)) {
            sum += c[i];
        }
        return sum;
    }

    // 区间查询：求 a[l] 到 a[r] 的和
    int range_query(int l, int r) {
        return query(r) - query(l - 1);
    }
};
```

## 3. 复杂度证明

- **时间复杂度（单次操作）：$O(\log N)$**
    
    在 `add` 或 `query` 操作中，循环变量 $i$ 每次加上或减去 $\text{lowbit}(i)$。因为任何一个正整数 $N$ 的二进制位数不超过 $\lfloor \log_2 N \rfloor + 1$。每次加上 `lowbit` 必然导致进位，从而减少或保持二进制中 `1` 的个数；每次减去 `lowbit` 必然消去一个 `1`。因此循环次数严格小于等于 $\log_2 N$，时间复杂度为 $O(\log N)$。
    
- **空间复杂度：$O(N)$**
    
    只需要开辟一个与原数组大小相同（通常下标从 1 开始，大小为 $N+1$）的数组 `c[]` 即可。
    
- **建树时间复杂度：$O(N)$**
    
    如果通过 $N$ 次 `add` 操作建树，时间是 $O(N \log N)$。但可以通过线性建树（直接遍历数组，把当前节点的值加到直接父节点 `i + lowbit(i)` 上）优化到严格 $O(N)$。

## 4. 可以维护什么样的数据？

树状数组本质上维护的是**前缀聚合信息**，因此对被维护的数据有特定的代数要求：


1. **必须满足结合律（Associativity）：** 因为树状数组将一段连续区间拆成了多个二进制长度的小区间，只有满足结合律的操作（如加法、乘法、异或），才能分块计算再合并。
    
2. **通常需要满足可差分性（Invertibility）：** 如果要进行任意区间 $[L, R]$ 的查询，操作必须有“逆运算”（如加法的逆是减法，异或的逆是它本身）。
    
    - **能完美维护：** 区间和（Sum）、区间异或和（XOR）、区间乘积（不含0或允许除法）。  
        
    - **受限维护：** 区间最大值/最小值（RMQ）。由于 $\max(a, b)$ 没有逆运算，树状数组求任意区间最大值非常麻烦，一般只用来求**前缀**最大值，或者在仅允许“单调修改”（比如只允许把元素改大）时使用。对于 RMQ，通常更推荐**线段树**或 **ST 表**。

## 5. 核心使用场景

树状数组常用于需要频繁修改并查询统计信息的场景，典型应用包括：

- **动态前缀和/区间和：** 最基础的用法（单点修改 + 区间查询）。
    
- **单点查询 + 区间修改：** 利用**差分数组**的思想。维护差分数组 $D[i] = A[i] - A[i-1]$ 的树状数组，区间修改 $[L, R]$ 加 $k$ 转化为单点修改 `add(L, k)` 和 `add(R+1, -k)`；单点查询 $A[x]$ 转化为求差分数组的前缀和 `query(x)`。
    
- **求逆序对（Inversion Count）：** 遍历数组的同时，将数值作为树状数组的下标（如果数值过大需要先离散化），每次统计树状数组中比当前数大的元素个数，可以 $O(N \log N)$ 解决逆序对问题，是归并排序之外最常用的解法。  
    
- **动态排名系统：** 配合权值树状数组（下标代表元素的大小，存储的值代表该元素出现的次数），可以快速查询某个数的排名，或者查询某个排名的数。
