Manacher算法（马拉车算法）是一种用于在字符串中查找**最长回文子串**的高效算法。它的核心优势在于将暴力解法的 $O(n^2)$ 时间复杂度优化到了**严格的 $O(n)$**。

以下是该算法的详尽原理解析及实现步骤。

### 一、 核心思想：利用回文的对称性

在传统的中心扩展法中，我们依次将每个字符（或两个字符的间隙）作为回文中心向两边扩展。这会导致大量重复计算。Manacher算法的核心在于：**利用已知回文串的对称性，直接跳过不必要的比较。**

### 二、 算法核心步骤

#### 1. 字符串预处理（消除奇偶长度差异）

回文串分为奇数长度（如 `aba`，中心是 `b`）和偶数长度（如 `abba`，中心是两 `b` 之间）。为了统一处理，我们在每个字符之间以及字符串首尾插入一个原字符串中未出现过的特殊字符（如 `#`）。

为了防止越界，通常还在首尾加上另外两个不同的特殊字符（如 `^` 和 `$`）。

**示例：**

原字符串：`babad`

预处理后：`^#b#a#b#a#d#$`

这样，所有寻找的回文串在处理后的字符串中都变成了奇数长度。

#### 2. 定义关键变量

- **`p[i]`（回文半径数组）**：以预处理后字符串的第 $i$ 个字符为中心，最长回文子串的**半径**（包括中心字符）。
    
    - _神奇的性质：_ `p[i] - 1` 正好等于原字符串中该回文串的总长度。
        
- **`c` (Center)**：当前已知的、右边界延伸得最远的回文串的**中心位置**。
    
- **`r` (Right)**：这个以 `c` 为中心的回文串的**最右侧边界**（即 $r = c + p[c]$）。
    

#### 3. 核心状态转移方程（复用计算结果）

当我们遍历到索引 $i$ 时，我们要计算 `p[i]`。此时 $i$ 必然在 $c$ 的右侧（即 $i > c$）。

我们找到 $i$ 关于中心 $c$ 的对称点 $j$（即 $j = 2c - i$）。

根据 $i$ 和 $r$ 的位置关系，分两种大情况：

**情况 A：$i < r$ （当前位置在已知最右边界内）**

由于回文的对称性，位置 $i$ 及其周围的字符，与位置 $j$ 及其周围的字符是完全对称的。因此可以得出：

$$p[i] \ge \min(r - i, p[j])$$

这里又可以细分为三种子情况来理解这个 `min`：

1. **$p[j]$ 的覆盖范围完全在 $c$ 的控制范围之内：** 即 $i + p[j] < r$。此时 `p[i]` 必定完全等于 `p[j]`，不需要再向外暴力扩展。
    
2. **$p[j]$ 的覆盖范围超出了 $c$ 的左边界：** 此时对称过来，$i$ 的回文半径最多只能保证到 $r$（即 $r - i$），超出 $r$ 的部分无法保证对称，需要继续暴力匹配。
    
3. **$p[j]$ 的范围刚好挨到 $c$ 的左边界：** 同样保证 `p[i]` 至少为 $r - i$，超出部分需继续暴力匹配。
    

**情况 B：$i \ge r$ （当前位置在已知边界外）**

之前的信息完全用不上，只能老老实实从头开始中心扩展，即先令 `p[i] = 1`，再向外匹配。

#### 4. 暴力扩展与更新边界

根据上述初始化的 `p[i]`，继续尝试向左右两边扩展：

`while (T[i + p[i]] == T[i - p[i]]) p[i]++;`

扩展结束后，如果当前算出的回文串右边界突破了原本的 $r$（即 $i + p[i] > r$），则更新 $c$ 和 $r$：

`c = i; r = i + p[i];`

### 三、 完整代码实现 

```C++
int manacher(const string& str) {
    if (str.empty()) return 0;

    // 对应原代码中的 manacherss 方法，预处理字符串
    int n = str.length() * 2 + 1;
    string ss(n, '#'); // 直接初始化为 '#'，省去后续的三元运算符判断的一部分
    for (int i = 0, j = 0; i < n; i++) {
        ss[i] = (i & 1) == 0 ? '#' : str[j++];
    }

    int max_len = 0; // 对应原代码的 max，为避免与 std::max 冲突修改了命名
    vector<int> p(n, 0); // 对应原代码的 p 数组，用于记录回文半径

    // 核心 Manacher 逻辑
    for (int i = 0, c = 0, r = 0, len = 0; i < n; i++) {
        // 如果在已知最右边界内，利用对称性加速；否则初始为 1
        len = r > i ? min(p[2 * c - i], r - i) : 1;
        
        // 中心扩展
        while (i + len < n && i - len >= 0 && ss[i + len] == ss[i - len]) {
            len++;
        }
        
        // 更新最大右边界 r 和对应的中心 c
        if (i + len > r) {
            r = i + len;
            c = i;
        }
        
        max_len = max(max_len, len);
        p[i] = len;
    }
    
    return max_len - 1;
}
```

### 四、 复杂度分析

- **时间复杂度：$O(n)$**
    
    虽然代码里有一个 `while` 嵌套在 `for` 循环中，但仔细观察会发现，只有当尝试匹配边界之外的新字符时，`while` 循环内部的 `p[i] += 1` 才会成功。而每次匹配成功，都会导致 `r` 的增大。由于 `r` 始终向右移动，且最大不超过预处理后字符串的长度 $2n+3$，因此内层循环的总执行次数不会超过字符串的长度。摊还分析下来，总时间复杂度严格为 $O(n)$。
    
- **空间复杂度：$O(n)$**
    
    需要额外的空间来存储预处理后的字符串 $T$ 以及回文半径数组 $p$，长度均为原字符串的 2 倍多，故空间复杂度为 $O(n)$。
